## 2. Explicitly NOT Represented in This Prototype (Out of Prototype Scope)

| Production / Infrastructure Area | Why Not Represented | Where Tracked |
|---|---|---|
| Live Sanity Studio authoring & `staging`/`production` dataset publishing | Prototype uses static deterministic synthetic fixtures (`js/fixtures.js`). No CMS writes or queries. | Internal Alpha Gates **A2**, **A5** |
| Server-authoritative Cloudflare Content Gateway & reader-local timezone embargo enforcement | Release/embargo checks in `js/state.js` are client-side simulations of the server contract; real security requires the Cloudflare Worker gateway. | Internal Alpha Gate **A3** |
| Real Supabase email OTP authentication, PostgreSQL RLS, server-side merge transaction, and private Card verifier | Account flows in `js/views-overlays.js` are explicitly labeled **simulated UX states** for `G08` UX validation only. | Internal Alpha / Beta Gates **A6**, **A7** |
| Production React + TypeScript `src/` shell integration (`src/App.tsx`, `src/shelf/policy.ts`, `src/hubContinue/`, `src/components/notebook/`, etc.) | Explicitly excluded by Glass Atlas boundary rules; discovered mismatches are recorded in [`RESIDUAL_ISSUES_REGISTER.md`](./RESIDUAL_ISSUES_REGISTER.md). | Future scoped production PRs (§12 handoff) |
| Native iOS / Android Capacitor packaging, OS universal links/deep-link handlers, push notifications, and real physical low-end Android performance qualification | Browser-only prototype; native platform behavior and physical device performance remain separate launch gates. | Internal Alpha / Beta Gate **A8**, Issue [#37](https://github.com/Bibleberry/Bibleberry/issues/37) |
| Final visual design system, production color tokens, typography licensing, Alexis Waid's authentic Card illustrations, and published theological manuscripts | Visual design is a candidate directional reference only; all copy and SVG illustrations are clearly marked synthetic placeholders. | §1.2, §12.2 |
| All 7 Challenge formats' intrinsic completion mechanics (e.g., interactive prayer/discipline formats beyond screen-stepped reading) | Prototype uses representative multi-screen reading Challenges with optional study/prayer blocks and explicit `Finish`. | §5.2, §12.2 |
