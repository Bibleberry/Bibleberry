# R20-3 iOS Simulator POC

## Scope and status

This is a development shell and unsigned simulator-build proof, not an App Store or device-distribution configuration. The source-controlled project was generated by Capacitor CLI 8.6.0 using its Swift Package Manager (SPM) template. No custom `CapApp-SPM` project content is maintained. The app keeps the existing temporary identifier `com.example.bibleberry.r20poc`, display name `Bibleberry R20-1 POC`, and shared `disableBackButtonHandler: true` setting. No production identity or signing team was added.

The generated project is in `ios/`. Its tracked source includes the Xcode project, App Swift/storyboard/plist/assets, Capacitor-managed `CapApp-SPM/Package.swift`, and CLI-generated support files. `ios/.gitignore` excludes copied web assets, generated Capacitor config, local build output, Pods, DerivedData, and Cordova plugin output; `CapApp-SPM/.gitignore` excludes SwiftPM build/cache state. Regenerate and synchronize managed files with the Capacitor CLI rather than editing them by hand.

The iOS Simulator workflow uses GitHub's fixed `macos-26` image and selects Xcode 26.4.1 (build 17E202), documented in the [runner-images macOS 26 image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-Readme.md). It pairs the iOS 26.4 Simulator SDK with the iOS 26.4 runtime (runtime build 26.4.1), which was present on the runner. The generated project sets its minimum iOS version to 15.0. It uses SPM; CocoaPods is not required.

The iOS Simulator SDK and the bootable Simulator runtime are separate Xcode components. CI records `xcodebuild -showsdks` and `xcrun simctl list runtimes`; if the iOS 26.4 runtime is absent, it downloads that runtime using `xcodebuild -downloadPlatform iOS -buildVersion 26.4` and installs the exported disk image with `xcodebuild -importPlatform`. It then enumerates project destinations before compiling. The pinned Xcode/SDK/runtime pair is supported by the hosted image inventory and the observed runner runtime list; missing components fail clearly rather than being silently skipped.

The first native run, [43076940894](https://github.com/Bibleberry/Bibleberry/actions/runs/43076940894), used runner image `macos-26-arm64` version `20261102.0473.1` and Xcode 26.0.1 (build 17A400). `npm ci`, the web build, Capacitor sync, and SPM dependency resolution passed. The build then exited 70 before Swift compilation because the iOS 26.0 Simulator platform/runtime was not installed; no `.app` was produced or validated.

The follow-up attempt [43082571779, job 130738622131](https://github.com/Bibleberry/Bibleberry/actions/runs/43082571779/job/130738622131) confirmed the distinction: Xcode 26.0.1 had the `iphonesimulator26.0` SDK, while available runtimes were iOS 26.2, 26.4 (build 26.4.1), and 26.5. Apple’s download service reported `iOS 26.0 is not available for download`, so this retry also stopped before compilation. The workflow now selects the documented Xcode 26.4.1 / iOS 26.4 pair already represented in that runner inventory.

This Linux session successfully generated and synchronized the iOS source, but has no `xcodebuild`, Apple SDK, or simulator. The corrected macOS runner has compiled and validated the unsigned simulator `.app`; that compile does not establish app launch or runtime/device behavior.

## Development and reproduction

Use Node.js 22 and npm. From the repository root, for a clean checkout before an iOS project has been generated:

```sh
npm ci
npm run build
npx cap add ios
```

`npx cap add ios` generates the SPM-backed `ios/App/App.xcodeproj` and syncs the current `dist/` output. The checked-in project is subsequently updated after each web build with:

```sh
npm run build && npx cap sync ios
```

On macOS with Xcode 26.4.1, the signing-free simulator build used by CI is:

```sh
sudo xcode-select --switch /Applications/Xcode_26.4.1.app/Contents/Developer
xcodebuild -version
xcodebuild -showsdks
xcrun simctl list runtimes
if ! xcrun simctl list runtimes -j \
  | python3 -c 'import json,sys; runtimes=json.load(sys.stdin)["runtimes"]; sys.exit(0 if any(r["name"] == "iOS 26.4" and r["isAvailable"] for r in runtimes) else 1)'; then
  mkdir -p "$TMPDIR/ios-simulator-runtime"
  xcodebuild -downloadPlatform iOS -buildVersion 26.4 \
    -exportPath "$TMPDIR/ios-simulator-runtime"
  RUNTIME_DMG="$(find "$TMPDIR/ios-simulator-runtime" -maxdepth 1 -type f -name '*.dmg' -print -quit)"
  test -n "$RUNTIME_DMG"
  xcodebuild -importPlatform "$RUNTIME_DMG"
fi
xcrun simctl list runtimes
xcodebuild -project ios/App/App.xcodeproj -scheme App -showdestinations
xcodebuild \
  -project ios/App/App.xcodeproj \
  -scheme App \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath "$TMPDIR/BibleberryDerivedData" \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY='' \
  build
```

The resulting app is at `$TMPDIR/BibleberryDerivedData/Build/Products/Debug-iphonesimulator/App.app`. CI asserts that it is nonempty, its bundle identifier is `com.example.bibleberry.r20poc`, it contains `public/index.html` and a bundled JavaScript asset, and then uploads that development `.app` for seven days. The artifact is not an IPA or a distribution build.
