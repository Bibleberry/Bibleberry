# R20-3 iOS Simulator POC

## Scope and status

This is a development shell and unsigned simulator-build proof, not an App Store or device-distribution configuration. The source-controlled project was generated by Capacitor CLI 8.6.0 using its Swift Package Manager (SPM) template. No custom `CapApp-SPM` project content is maintained. The app keeps the existing temporary identifier `com.example.bibleberry.r20poc`, display name `Bibleberry R20-1 POC`, and shared `disableBackButtonHandler: true` setting. No production identity or signing team was added.

The generated project is in `ios/`. Its tracked source includes the Xcode project, App Swift/storyboard/plist/assets, Capacitor-managed `CapApp-SPM/Package.swift`, and CLI-generated support files. `ios/.gitignore` excludes copied web assets, generated Capacitor config, local build output, Pods, DerivedData, and Cordova plugin output; `CapApp-SPM/.gitignore` excludes SwiftPM build/cache state. Regenerate and synchronize managed files with the Capacitor CLI rather than editing them by hand.

The iOS Simulator workflow uses GitHub's fixed `macos-26` image and selects Xcode 26.0.1 (build 17A400), documented in the [runner-images macOS 26 image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-Readme.md). The generated project sets its minimum iOS version to 15.0. It uses SPM; CocoaPods is not required.

This Linux session successfully generated and synchronized the iOS source, but has no `xcodebuild`, Apple SDK, or simulator. The Xcode compilation and simulator artifact validation therefore remain pending the macOS workflow. App launch and device behavior are not inferred from source generation or compilation.

## Development and reproduction

Use Node.js 22 and npm. From the repository root, for a clean checkout before an iOS project has been generated:

```sh
npm ci
npm run build
npx cap add ios
```

`npx cap add ios` generates the SPM-backed `ios/App/App.xcodeproj` and syncs the current `dist/` output. The checked-in project is subsequently updated after each web build with:

```sh
npm run build && npx cap sync ios
```

On macOS with Xcode 26.0.1, the signing-free simulator build used by CI is:

```sh
sudo xcode-select --switch /Applications/Xcode_26.0.1.app/Contents/Developer
xcodebuild \
  -project ios/App/App.xcodeproj \
  -scheme App \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath "$TMPDIR/BibleberryDerivedData" \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY='' \
  build
```

The resulting app is at `$TMPDIR/BibleberryDerivedData/Build/Products/Debug-iphonesimulator/App.app`. CI asserts that it is nonempty, its bundle identifier is `com.example.bibleberry.r20poc`, it contains `public/index.html` and a bundled JavaScript asset, and then uploads that development `.app` for seven days. The artifact is not an IPA or a distribution build.
